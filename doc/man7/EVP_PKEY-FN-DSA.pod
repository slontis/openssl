=head1 NAME

EVP_PKEY-FN-DSA, EVP_KEYMGMT-FN-DSA,
EVP_PKEY-FN-DSA-512, EVP_PKEY-FN-DSA-1024
- EVP_PKEY FN-DSA keytype and seed support

=head1 DESCRIPTION

The default provider supplies the B<FN-DSA-512> and B<FN-DSA-1024> key types,
identified by B<EVP_PKEY_FN_DSA_512> and B<EVP_PKEY_FN_DSA_1024>.
They support key generation, import, export, duplication, validation, and
encoding as PKCS#8 private keys and SubjectPublicKeyInfo public keys.
They are omitted when OpenSSL is configured with B<no-fn-dsa>.
Object names and identifiers remain available in that configuration.

This development implementation uses fixed-point key generation and retains
the seed from which the public key and internal private-key cache are derived.
The seed lifecycle follows the ML-DSA key implementation.
See L</Implementation status> for the specification and interoperability limits.

=head2 Keygen Parameters

=over 4

=item "seed" (B<OSSL_PKEY_PARAM_FN_DSA_SEED>) <octet string>

A 32-byte seed used to generate the private and public components deterministically.
If omitted, a new seed is generated using the library context's private DRBG.
Generated keys retain their seed. It is available as a gettable parameter,
is exported when private components are selected, and is preserved by private-key
duplication. Public-only exports and copies omit the seed and private cache.

As with ML-DSA, repeatable key generation uses this seed parameter rather than
the signature parameters C<deterministic> or C<test-entropy>.
The generation context copies the supplied seed. Repeated generation from
that context reproduces the same public and private key components.
Supplying an empty seed parameter clears the configured seed, restoring fresh
random generation on each call. Other lengths besides 32 bytes are rejected.

Loading a seed-format PKCS#8 private key regenerates both key components.
The seed is private key material and is cleared when its owning key is freed
or reset.

Seed expansion performs the complete key-generation procedure, including the
NTRU solver and candidate rejection. It is slow compared with loading an
already expanded key. Seed-only PKCS#8 saves storage but incurs this cost on
every private-key load. Applications that sign repeatedly should retain and
reuse the initialized B<EVP_PKEY>; subsequent signatures use its cached expanded
key and do not regenerate it. Repeatedly importing the same seed or decoding
its PKCS#8 repeats the key-generation work.

=item "properties" (B<OSSL_PKEY_PARAM_PROPERTIES>) <UTF8 string>

The property query used when fetching SHAKE-256 for key generation.

=back

Set these parameters with L<EVP_PKEY_CTX_set_params(3)> after
L<EVP_PKEY_keygen_init(3)>.

=head2 Common FN-DSA parameters

The common information parameters are described in
L<provider-keymgmt(7)/Common Information Parameters>.
The following parameters can be retrieved with L<EVP_PKEY_get_params(3)> or
L<EVP_PKEY_get_octet_string_param(3)>.
They are accepted by L<EVP_PKEY_fromdata(3)> and returned by
L<EVP_PKEY_todata(3)> for the appropriate selection.
Once key material is initialized, it cannot be replaced or augmented.

=over 4

=item "seed" (B<OSSL_PKEY_PARAM_FN_DSA_SEED>) <octet string>

The retained 32-byte private seed. Importing a seed regenerates the key pair.
If a public key or expanded private cache is also supplied, it must match
the regenerated key; otherwise import fails.

=item "pub" (B<OSSL_PKEY_PARAM_PUB_KEY>) <octet string>

The encoded public key: 897 bytes for B<FN-DSA-512> or 1793 bytes for
B<FN-DSA-1024>. Its parameter-set header and coefficient encoding are checked.

=item "priv" (B<OSSL_PKEY_PARAM_PRIV_KEY>) <octet string>

The internal expanded private cache: 1281 bytes for B<FN-DSA-512> or 2305 bytes
for B<FN-DSA-1024>. This is a development representation for internal key
operations and raw import/export, not a standardized FN-DSA private-key format.
Import validates the private-key equation and bounds, and derives its public key.
Importing only this cache does not recover the original seed.

=back

=head2 Key encoding

The supported private-key encoding follows the seed proposal in Section 6 of
L<draft-ietf-lamps-fn-dsa-certificates-00|https://datatracker.ietf.org/doc/html/draft-ietf-lamps-fn-dsa-certificates-00#section-6>.
The PKCS#8 C<privateKey> OCTET STRING contains the 32 seed bytes directly.
It contains no additional ASN.1 wrapper or expanded cache.
PrivateKeyInfo and encrypted EncryptedPrivateKeyInfo are supported in DER and PEM.
Encoding a cache-only key as PKCS#8 fails because its seed is unavailable.

SubjectPublicKeyInfo contains the public-key bytes in a BIT STRING with zero
unused bits. AlgorithmIdentifier parameters must be absent for both public and
private keys. Unexpected parameters, wrong identifiers, noncanonical encodings,
trailing bytes, and expanded private-key payloads are rejected.
Nonempty C<output_formats> overrides are unsupported and are rejected.

Text output uses the shared encoder framework, as for ML-DSA.
L<EVP_PKEY_print_public(3)> prints the algorithm name and C<pub> bytes.
L<EVP_PKEY_print_private(3)> additionally prints the C<priv> cache and,
when retained, the C<seed>. A cache-only private key can be printed without
a seed. Public-key selection prints only public material, including when the
key also contains private components. Text output is for inspection;
it is not a supported input format.

=head2 Names and identifiers

B<FN-DSA-512> also has the provider aliases B<FNDSA512>, B<id-alg-fndsa512>,
and B<2.16.840.1.101.3.4.3.50>.
B<FN-DSA-1024> also has the aliases B<FNDSA1024>, B<id-alg-fndsa1024>,
and B<2.16.840.1.101.3.4.3.51>.
These numeric identifiers are the provisional values selected for this
development branch; their official assignment has not been independently verified.

=head2 Implementation status

This is not a validated FIPS 206 implementation. The private-seed encoding in
the referenced IETF draft is explicitly provisional.
The current development KeyGen feeds the 32 seed bytes directly into SHAKE-256
and consumes its output in the existing 32.32 fixed-point key generator.
Its exact seed-to-key mapping must be checked against the eventual normative
FN-DSA procedure before interoperability or standards conformance is claimed.

The default provider also supplies the experimental fixed-point signing profile
described in L<EVP_SIGNATURE-FN-DSA(7)>. It uses ML-DSA's pure message framing
for contexts up to 255 bytes; its signing vectors still
need alignment with normative FN-DSA. The keys are not supplied
by the FIPS provider, and no FIPS approval indicator is available.

=head1 EXAMPLES

Generate a key with a new random seed:

    EVP_PKEY *key = EVP_PKEY_Q_keygen(NULL, NULL, "FN-DSA-512");

Generate a key from an application-supplied seed:

    #include <openssl/core_names.h>
    #include <openssl/evp.h>
    #include <openssl/params.h>

    EVP_PKEY *generate_from_seed(const unsigned char seed[32])
    {
        EVP_PKEY_CTX *ctx;
        EVP_PKEY *key = NULL;
        OSSL_PARAM params[2];

        params[0] = OSSL_PARAM_construct_octet_string(
            OSSL_PKEY_PARAM_FN_DSA_SEED, (void *)seed, 32);
        params[1] = OSSL_PARAM_construct_end();
        ctx = EVP_PKEY_CTX_new_from_name(NULL, "FN-DSA-512", NULL);
        if (ctx == NULL || EVP_PKEY_keygen_init(ctx) <= 0
            || EVP_PKEY_CTX_set_params(ctx, params) <= 0
            || EVP_PKEY_generate(ctx, &key) <= 0) {
            EVP_PKEY_free(key);
            key = NULL;
        }
        EVP_PKEY_CTX_free(ctx);
        return key;
    }

Retrieve the retained seed:

    unsigned char seed[32];
    size_t seed_len;

    if (EVP_PKEY_get_octet_string_param(key, OSSL_PKEY_PARAM_FN_DSA_SEED,
            seed, sizeof(seed), &seed_len) > 0) {
        /* Use the private seed. */
    }
    OPENSSL_cleanse(seed, sizeof(seed));

Generate a seed-format private key and extract its public key with the command
line tools:

    openssl genpkey -algorithm FN-DSA-512 -out private.pem
    openssl pkey -in private.pem -pubout -out public.pem

Inspect the private or public components:

    openssl pkey -in private.pem -text -noout
    openssl pkey -pubin -in public.pem -text -noout
